Found by verifying Two new failure shapes — both from the catalogue

11th · brand voice gone again, silently

POSTGRES_URL entered the MAS .env (milestone v1.5) for other workflows. With the DSN present, the consult went to pg_store — where marketing was never ingested — received [] without error, and the round-6 local fallback was never reached. From that day every F31 prompt lost BRAND-VOICE again. The code's own comment described the scenario it "prevented" — but only covered "no DSN", not "DSN and empty collection".

Fix: probe at construction; pg empty + local has the collection → serve local (RBAC identical). test_consult_pg_empty_fallback.py locks it.

12th · count=0 with 18 pairs on disk

The official dashboard, started by a scheduled task, served /stats: count 0. The router built ContentPairStore() with the default Path("data") — relative to the process cwd. The runtime already anchored its copy to the repo root; the router was a second reader with a different answer. Fix: anchor both stores; proven by reading 18 pairs from /tmp.

Baseline, so the improvement is measurable: /api/posts?stats=1 on the 53 existing posts — 32 distinct sources, repeat_ratio 0.40 (two of every five posts reused a source), by_vertical all "unknown". New posts carry a vertical; the number is trackable from here.
